# 클래스 구조

---
1. Car
> 게임에 참여하는 자동차 객체
>
> 고유 번호, 이동 거리를 필드로 가짐
> 

2. ParticipantList
> 경주에 참여하는 모든 자동차를 리스트로 관리
> 
> 입력된 값 만큼 참여하는 자동차 초기화
> 
> 게임 규칙을 매개변수로 입력받아서 각 자동차에 주입함
> 
> 모든 자동차에 대해 경주 상태(이동 거리 현황)를 출력함

3. RacingRule
> 경주에 적용할 규칙 인터페이스
> 
> 경주 방식을 결정하는 메서드 구현

4. RandomMoveRule
> RacingRule 구현체
> 
> 0~9 범위의 임의 값이 4 이상이면 1만큼 이동
> 
> 미만인 경우 움직이지 않음

5. RacingGame
> participantList 초기화
> 
> RacingRule 주입
> 
> 입력 횟수만큼 경기 진행 및 결과 출력

6. Main
> 사용자로부터 값을 입력받음
> 
> 실질적으로 사용할 경주 규칙 선택 및 생성
> 
> RacingGame 클래스를 생성하고 startRace() 메서드를 호출하여 경주를 시작하고 결과까지 출력하여 확인함

# 클래스의 책임과 연결 관계

---
1. RacingGame
> Main에서 실질적으로 경주를 위해 사용할 클래스로 설계하였다.
> 
> RacingGame 생성자를 통해 RacingRule 클래스와 ParticipantList를 주입받아 내부에서 사용한다.

2. ParticipantList
> 사실 클래스 이름이 조금 아쉬운 거 같다 ParticipantManagement 이런게 더 나은 것 같다.
> 
> 실질적으로 생성된 Car 객체들에 대해 일괄적으로 Car 클래스의 메서드를 호출한다.
> 
> 각 자동차별 이동 과정과, 이동 상태 결과를 확인한다.

3. RacingRule
> 각 자동차들이 어떻게 움직일지 규칙을 다양하게 적용할 수 있다고 생각해 인터페이스 선언
> 
> 구현체별 각기 다른 과정으로 움직이지 말지 결정하여 최종으로 움직일 거리를 반환하는 raceProcess() 메서드 선언

4. Car
> 특정 클래스에 의존하지 않음
> 
> 어느정도 움직일지 결정하는 drive() 클래스에서 매개변수로 이동 거리를 입력받음

# 회고
